# Repository instructions

Before any work, read this file, [MASTER_PROMPT.md](MASTER_PROMPT.md), [progress.md](progress.md), [PROJECT_STATE.json](PROJECT_STATE.json), [PLANS.md](PLANS.md) and [DECISIONS.md](DECISIONS.md) in that order. Read the relevant research and engineering notes, then inspect Git status and recent commits. Resume from verified repository state.

- MASTER_PROMPT.md is the complete v1.0 contract. The v0.2 review is historical evidence. See research/INPUT_RECONCILIATION.md for decisions.
- Read [CONTINUATION_V1.md](CONTINUATION_V1.md) for the owner’s roadmap from the published demo to v1.0.0.
- Read [FINAL_COMPLETION.md](FINAL_COMPLETION.md) for the final development and UI editorial contract.
- Preserve the owner-approved production UI. Read [docs/UI_DESIGN.md](docs/UI_DESIGN.md) before changing the web app. Use the existing navigation, typography, palette, spacing and layouts for new capabilities. Make visible changes only for functionality, accessibility or usability. Compare affected views with the production reference screenshots and record intentional differences.
- Keep rights, integrity, replication, statistical validation, frozen evaluation, claim safety and deployment gates explicit. Use fictional fixtures until rights permit analysis. Keep raw and row-level derivatives, credentials and private artifacts outside Git and releases.
- For Haryana, read [docs/HARYANA_RESEARCH.md](docs/HARYANA_RESEARCH.md) and [research/HARYANA_PROTOCOL.md](research/HARYANA_PROTOCOL.md). Split whole PHCs, preserve sub-center assignment blocks, and keep village counts separate from patient outcomes. Treat the conditional policy analysis and its nominal intervals as exploratory. Check [dataset feasibility](research/DATASET_FEASIBILITY.md) for the licensed Sierra Leone follow-up.
- Preserve the frozen trial benchmark manifest and labels. Record any future extractor development against separate cases and require a new independent holdout for a new quality claim.
- Keep evidence separate from fictional inputs. Never report clinical outcomes, model quality, safety checks or deployment without corresponding verification.
- Use only the intended GitHub and Cloudflare accounts and zero-additional-cost services. Release only a verified allowlisted static build.
- Record important decisions, tests, evidence, blockers and next actions in the repository during work. Before ending, synchronize progress.md and PROJECT_STATE.json, and commit verified changes. Use git log to resolve the current checkpoint and leave no dependency on agent history.
